# Summary
Defines, formally and with strong typing, the on-disk payload format for every
scientific result kind MFDB stores (FCS correlations, spectra, TTTR references,
TCSPC decays, burst tables and selections, anisotropy curves, PDA histograms,
and more). It replaces ad-hoc, lossy JSON serialization with a single
msgpack-based, schema-validated codec module exposing `encode_payload`,
`decode_payload`, and `get_payload_schema`, using a self-describing envelope so
decoding needs no external hint. Today `data_format` is a free-text label that
drives no deserialization, DataFrames and dicts are serialized losslessly-poorly,
and there is no formal schema per kind; this codec becomes the sole
(de)serialization choke point.

# Status
Done. Foundational layer (named with the `0X0` convention like the ORM mapping)
that is a hard prerequisite for the result registry.

# Goal
Define, formally and with strong typing, the on-disk payload format for every
scientific result kind MFDB stores. Replace the current ad-hoc, lossy JSON
serialization with a msgpack-based, schema-validated codec layer that round-trips
losslessly and is self-describing. The deliverable is a small, well-tested module
— `payload_codec.py` — exposing:

```python
blob, data_format = encode_payload(kind, obj)   # typed object -> bytes
obj               = decode_payload(blob)          # bytes -> typed object (self-describing)
schema            = get_payload_schema(kind)      # the formal schema for a kind
```

`register_result()` (PRD-03) and any `read_result()` call **only** these
functions. No plugin or registry code serializes payloads by hand.

# Why this is needed
- `data_format` on `mfdb_artifact` is a free-text label (`json`, `csv`, `hdf5`, …)
  that drives no deserialization; `MFDatabase.get_object()` returns raw `bytes`
  and the caller must guess how to parse them.
- `register_result()` serializes DataFrames via `to_json(orient="records")` and
  dicts via `json.dumps()` — lossy: dtype, column order, array shape, units,
  NaN/inf, and the distinction between an FCS curve and a spectrum are all lost.
- Three inconsistent storage idioms already exist: object-store bytes, the typed
  `analysis_data` table (x/y float64 blobs + units), and `add_spectrum`
  (float64 blobs + units) — none general or self-describing.
- No formal schema describes what a payload of a given `kind` must contain.

Consequences: write-only data, uneven provenance, no validation, no safe
round-trip.

# Design decisions (locked)
1. **msgpack, not JSON** — compact, binary, typed, fast (`msgpack==1.1.2` already
   installed; `msgpack_numpy` declared as a runtime dependency). The codec may
   still encode arrays explicitly to keep the envelope stable.
2. **Self-describing envelope** — every blob is a msgpack map:
   `{v, kind, schema, units, meta, body}` (envelope version, result kind, body
   schema version, unit annotations, small JSON-safe metadata, the typed
   validated payload) so `decode_payload()` needs no external hint.
3. **`data_format` becomes meaningful and mostly closed** — add `"msgpack"` to
   `DATA_FORMATS`; payloads from this layer set `data_format="msgpack"`. Raw
   vendor measurement files (ptu/spc/bh/photon_hdf5) keep their format labels and
   are referenced, not rewritten.
4. **Strong typing at the boundary** — each kind has a dataclass (in-memory type)
   and a formal schema (field names, dtypes, shapes, required/optional, units).
   Encoding validates the object; decoding validates the blob and returns the
   dataclass. Failures raise `PayloadSchemaError` — bugs, not silent.
5. **Reading routines define the schemes** — the canonical schema per kind is
   derived from a single source of truth (the dataclass + a `FIELDS` spec), and
   the decoder is generated from it, so writer and reader never drift.
6. **Align with flrCIF where the bundled dictionary matches** — field names stay
   Pythonic and stable, but `get_payload_schema()` exposes `flrcif_item_id`
   metadata for matched fields; those IDs come from the ChiSurf parameter
   registry / chinet translation layer and must resolve in the bundled
   mmCIF/flrCIF dictionaries. Do not invent IDs for raw arrays with no
   dictionary item.

# Array encoding
Numpy arrays round-trip as a small typed sub-map so they survive exactly and keep
the envelope stable even with `msgpack_numpy` installed:

```python
def _encode_array(a): a = np.ascontiguousarray(a); return {"__ndarray__": True, "dtype": str(a.dtype), "shape": list(a.shape), "data": a.tobytes()}
def _decode_array(d): return np.frombuffer(d["data"], dtype=np.dtype(d["dtype"])).reshape(d["shape"])
```

`data` is raw little-endian bytes; `dtype` is preserved exactly. Pack with
`use_bin_type=True` so `bytes` survive as `bin`. Float dtypes preserve NaN/inf
natively via `tobytes()`.

# Payload kinds (formal schemas)
Each kind has a dataclass in `payload_models.py`, a `FIELDS` spec, and a schema
version. Units live in the envelope `units` map. Required = R, optional = O.
- **`fcs_correlation`** — `lag` f64[n] R, `correlation` f64[n]/[m,n] R (2D for
  ACF/CCF), `error` O, `curve_names` O, `weights` O; units lag=s, correlation=1.
- **`spectra`** — `wavelength` f64[n] R (nm), `intensity` f64[n] R,
  `spectrum_type` str R (absorption/emission/excitation), `normalized` O.
- **`tcspc_decay`** — `time` f64[n] R (ns), `counts` i64/f64[n] R, `irf` O,
  `channel` O, `adc_resolution_ns` O (flrCIF `_flr_chisurf_parameter.dtTAC[ns]`),
  `micro_time_resolution_ns` O (flrCIF `…dtMT[ns]`).
- **`anisotropy_curve`** — `time` R (ns), `vv` R (parallel), `vh` R
  (perpendicular), `l1`/`l2` O (flrCIF `…l1`/`…l2`), `g_factor` O (flrCIF `…g`).
- **`pda_histogram`** — `edges` f64[k+1]/list R, `counts` f64[…] R (ndim = axes),
  `axis_names` O (e.g. `["E","S"]`).
- **`burst_table`** — `columns` list[str] R, `dtypes` list[str] R, `data`
  dict[str, ndarray] R (columnar so dtype/order survive); `to_dataframe()`/
  `from_dataframe()` convert losslessly.
- **`burst_selection`** — `source_artifact_id` O, `burst_ids` i64[n] O,
  `start_indices`/`stop_indices` u64[n] O, `mask` bool[n] O, `criteria` dict O,
  `labels` O; at least one of burst_ids / start+stop / mask required.
- **`tttr_reference`** — reference to a preserved raw file (not re-encoded):
  `source_artifact_id` R, `vendor_format` R (ptu/spc/bh/photon_hdf5),
  `n_records` O, `routing_channels` O, macro/micro time resolutions O,
  `header_json` O, `tags` O. The raw file is registered as a normal
  `raw_measurement` artifact; this kind carries the structured header so the
  stream is queryable without parsing.
- **`tttr_photon_stream`** — optional open msgpack derivative of a vendor file:
  `macro_times` u64[n] R, `micro_times` u32[n] R, `routing_channels` R,
  `event_types` O, macro/micro time resolutions (s) R, plus source/vendor/record/
  container/header/tags metadata. All event arrays same length; header/tag maps
  JSON-safe.
- **`generic_table` / `generic_curve`** — fallbacks; `generic_curve` = `{x, y,
  ex?, ey?, mask?}` mirroring `chisurf.core.data.DataCurve`; `generic_table` =
  same shape as `burst_table`. A typed path before a bespoke kind exists.

# Tasks
1. **Add the `msgpack` format + deps** — add `"msgpack"` to `DATA_FORMATS` in
   `models.py`; confirm `msgpack` and `msgpack-numpy` as runtime dependencies and
   install them in the arm64 conda environment.
2. **Payload models** (`payload_models.py`) — one `@dataclass` per kind
   (`FcsCorrelation`, `Spectrum`, `TcspcDecay`, `AnisotropyCurve`, `PdaHistogram`,
   `BurstTable`, `BurstSelection`, `TttrReference`, `TttrPhotonStream`,
   `GenericCurve`, `GenericTable`) declaring `SCHEMA_VERSION`, `KIND`, and a
   `FIELDS` spec (`field -> (dtype-or-type, required, unit)`). A tiny type
   mini-language (`"f8[]"`, `"i8[]"`, `"str[]"`, `"f8"`, `"str"`, `"bool"`,
   `"int"`) keeps it declarative; the codec and validator are generated from
   `FIELDS`. Models may declare `FLRCIF_ITEMS = {"field": "_category.item"}` for
   exact dictionary mappings, verified through the registry translation and
   `MmcifDictionary.load_bundled()`.
3. **The codec** (`payload_codec.py`) — `encode_payload(kind, obj, *, meta=None)
   -> (bytes, "msgpack")`, `decode_payload(blob) -> Any`,
   `get_payload_schema(kind) -> dict`, `class PayloadSchemaError(ValueError)`,
   and a `REGISTRY: dict[str, type]` mapping `kind -> dataclass`. Encode builds
   the envelope and packs with `use_bin_type=True`; decode unpacks with
   `raw=False`, checks `v`, looks up the model, migrates older `schema` versions
   via per-kind upgraders, validates (every R field present, dtype/shape per the
   mini-language, no unexpected body keys), and reconstructs arrays.
4. **pandas / DataCurve interop** — `BurstTable.from_dataframe()`/`.to_dataframe()`
   (columnar, dtype-preserving); `GenericCurve.from_data_curve()`/`.to_data_curve()`
   bridging `chisurf.core.data.DataCurve`, replacing `DataCurve.to_dict()` JSON
   round-tripping for archival.
5. **Migration shims** — adapters mapping existing typed storage onto codecs
   without a data migration: `analysis_data` (x/y blobs + units) ↔ `GenericCurve`/
   `tcspc_decay`; `add_spectrum` (blobs + units) ↔ `Spectrum`. New writes go
   through codecs; old rows stay readable via adapters.
6. **Tests** (`test/fio/test_payload_codec.py`) — round-trip each kind (arrays
   equal, dtypes identical, units preserved); NaN/inf survive; 2D correlation and
   2D histogram keep shape; `BurstTable` ↔ DataFrame preserves order/dtypes;
   missing-required / wrong-dtype-or-shape / unknown-kind raise
   `PayloadSchemaError`; schema-version migration path works; blob-size sanity
   (a 10k-point float64 FCS curve encodes to ~`n*8` bytes, proving no JSON
   bloat); flrCIF alignment (`g`, `l1`, `l2`, `dtTAC[ns]`, `dtMT[ns]` resolve in
   the bundled dictionary and match the ChiSurf parameter translation).

# Boundary / non-goals
- Not a new storage backend — payloads still go into the existing
  content-addressed object store via `MFDatabase.put_object`; this PRD defines
  only the bytes that go in.
- Not a mandatory TTTR re-encoding effort — raw photon streams stay in vendor
  formats unless a reader explicitly creates an open `tttr_photon_stream`
  derivative.
- Not sample/provenance modeling — that is PRD-02 / PRD-03.
